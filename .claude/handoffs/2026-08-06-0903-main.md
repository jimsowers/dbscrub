## 3. Important decisions already made

Do not re-litigate these. Full reasoning with rejected alternatives is in
`docs/DECISIONS.md` — read D27 and D28 there rather than re-deriving.

**D27 (unique indexes), both settled by the user directly:**
- Refuse ALL non-distinct strategies on a unique column — `static`, `null` AND
  bare `scramble`. Rejected: refusing only the constants.
- Refuse composite unique indexes **conservatively**, per column, without
  reasoning about whether the other columns still vary. Rejected: refusing only
  when the whole index collapses; rejected as gold-plating: a carve-out when the
  index's untouched columns contain the primary key.

**D28 (the splice), scope settled by the user:**
- Fix the collision in the same PR rather than documenting it or narrowing D27.
- A `#` delimiter, NOT fixed-width zero-padded keys (padding destroys shape
  preservation on short values — that alternative is closed).
- `unique: "key"` needs a whole-number key (allowlist: tinyint/smallint/int/
  bigint). Rejected: widening the verify gate to excuse hex, because a rule that
  excuses MORE is the dangerous direction (D17).
- The renderability check is a DENYLIST, deliberately unlike the splice
  allowlist. The two ask different questions; see D28.
- No fixture for binary keys. A unit test with a `varbinary` key column is the
  proportionate cover.

**Process:**
- `docs/DECISIONS.md` is the artifact to protect as this grows. It is why a cold
  session can tell what was already rejected and why. Linear issues should point

  investigated. It matters only if stamp freshness is ever reasoned about.
- **The masked-output shape CHANGED this session.** `Xxxxx42` is now `Xxxxx#42`,
  and `scramble` + `unique` needs one more character of column width than
  before. Anything written against the old shape is stale.
- **`config/aavsb.masking.json` still does not exist.** The tool is finished and
  has nothing real to run against. `docs/HANDOFF.md` calls this "the thing that
  actually blocks value" and it is the user's work, not code work — a strong
  candidate for the first Linear issue.
- **Method note worth carrying forward:** D28 was found only because writing
  D27's refusal required asserting that `scramble`+`unique` produces distinct

  of trusted. The probe found 99 collisions in 5,000 rows. Verify the guarantee
